# Агрегатор новостей (GitHub Pages)

Статический сайт-агрегатор: выбираете одну или несколько категорий, получаете общую ленту свежих новостей.

Возможности:
- выбор нескольких категорий;
- фильтр по источникам: любой источник можно выключить, выбор сохраняется на устройстве;
- отдельный раздел с новостями об искусственном интеллекте;
- раздел «Кибербезопасность»: атаки, уязвимости, утечки, вредоносное ПО;
- раздел «Фондовый рынок»: биржевые сводки, индексы, акции, облигации, IPO,
  дивиденды, а также карта рынка и бегущая строка котировок Московской биржи;
- карточки с картинкой и кратким описанием; первой в ленте идёт самая свежая
  новость с картинкой из первой порции, остальные строго по времени;
- бесконечная лента (порционная отрисовка);
- просмотр текста в модальном окне + ссылка на первоисточник.

Интерфейс оформлен как новостное издание: светлая и тёмная темы, навигация по темам со счётчиками,
крупная первая публикация и адаптивная сетка. На телефоне темы доступны в
горизонтальном меню. Режим чтения поддерживает изменение размера текста,
управление с клавиатуры и возврат фокуса к открытой карточке. Выбранные темы
размер текста и выбранная цветовая тема сохраняются на устройстве. До первого
ручного переключения тема следует системной настройке браузера.

Раздел `ai.html` показывает только материалы об ИИ. Сборщик присваивает им
категорию по русским и английским терминам, названиям ключевых моделей и
компаний. До следующего запуска сборщика та же классификация применяется в
браузере к текущему срезу новостей.

Проверить основные сценарии интерфейса (после `npm ci`):

```bash
npm run test:ui
```

Тесты проверяют фильтрацию и порционную загрузку на текущем `data/news.json`,
сохранение настроек, окно чтения, ошибки загрузки и повторные запросы.
Они выполняются в jsdom и не заменяют визуальную проверку в браузере.

## Как включить GitHub Pages
1. Запушьте репозиторий в GitHub.
2. GitHub: Settings -> Pages.
3. Source: "Deploy from a branch".
4. Branch: `main` / folder: `/ (root)`.

После этого откройте Pages URL.

## Локальный запуск
Можно открыть `index.html` напрямую, но надёжнее через локальный сервер:

```bash
node dev-server.js
```

## Откуда берётся текст новостей
Браузер **не может надёжно** скачать «полный текст» с сайтов новостей напрямую (CORS/пейволлы/защита).
Поэтому лента читает готовый срез, который собирается отдельным скриптом.

Срез состоит из двух частей:
- `data/news.json` — индекс: только то, что нужно карточкам (заголовок, описание
  не длиннее 500 символов, картинка, источник, дата, разделы). Его лента
  загружает при открытии и при проверке обновлений;
- `data/articles/<id>.json` — текст одной статьи для окна чтения. Такой файл
  запрашивается только когда статью открыли, и потом кешируется на странице.

Сборщик открывает страницу каждой новой записи и извлекает из неё текст
(Readability), чтобы новости читались на сайте, а не по ссылке. За один запуск
обрабатывается до 400 страниц, самые свежие первыми; страница, не давшая
текста, повторяется ещё дважды и затем оставляется в покое. У таких записей
в окне чтения показывается описание и ссылка на источник.

Проверка обновлений идёт условным запросом: если срез не менялся, сервер
отвечает «не изменилось» без тела, и повторные проверки почти ничего не стоят.

Картинка берётся из фида (`enclosure`, `media:content`, `media:thumbnail`,
`<img>` в описании). Если фид её не дал, сборщик открывает страницу статьи и
берёт превью из Open Graph или Twitter-карточки. Такой запрос делается только
для новостей не старше суток и в пределах общего лимита страниц за запуск
(200), поэтому у части старых записей картинки может не быть.

Сгенерировать данные локально:

```bash
npm install
npm run build:data
node dev-server.js
```

Источники и правила категоризации настраиваются в `data/feeds.json`.
Сейчас подключены общие издания (Lenta.ru, ТАСС, Интерфакс, Коммерсантъ, РБК,
Ведомости), технологические (Хабр, 3DNews, CNews), научный N + 1 и издания о
кибербезопасности (Хакер, SecurityLab, BleepingComputer, The Hacker News)
и о рынках (Финам, Investing.com).
Сборщик понимает RSS 2.0 и Atom. Недоступный или сломанный фид не останавливает
сборку: ошибка попадает в лог, остальные источники собираются как обычно.

## Как новости попадают в разделы
Раздел новости определяется рубрикой, в которой её разместил сам источник:
это значение `<category>` из RSS, а для ТАСС и Интерфакса, у которых раздел
закодирован в адресе статьи, ещё и первый сегмент пути (`/politika`, `/world`).
Ключ вида `/politika` в `categoryMap` точнее рубрики из RSS и имеет приоритет.
Рубрики сравниваются без учёта регистра и обрамляющих дефисов и косых черт
(«- игры», «Наука/»); рубрика с подрубрикой («Политика / Международные
новости») при отсутствии своего правила наследует правило родителя.

Раздел по умолчанию (`defaultCategoryForSource`) задаётся только источникам,
которые целиком посвящены одной теме (Хабр, 3DNews, CNews, N + 1, Хакер,
The Hacker News). SecurityLab и BleepingComputer публикуют и общие новости о
технологиях и науке, поэтому у них раздел определяется рубрикой фида.

Рубрика источника сопоставляется только с тем разделом сайта, которому она
действительно соответствует. Если подходящего раздела нет (например, «Авто»,
«Из жизни» и «Путешествия» на Lenta.ru), новость в ленту не попадает, а не
ставится в чужой раздел. Поверх этого к любой новости добавляются сквозные темы
«ИИ», «Кибербезопасность», «Фондовый рынок» и «Здоровье» по тексту заголовка
и описания. Раздел «Фондовый рынок» вложен в «Бизнес»: рыночная новость
попадает в оба раздела. Для Хабра дополнительно учитываются хабы: «Информационная безопасность» даёт раздел
«Кибербезопасность», хабы о машинном обучении — раздел «ИИ».

Правила для «Фондового рынка» двухуровневые. Однозначные термины (мосбиржа,
котировки, дивиденды, облигации, ОФЗ, IPO, фьючерсы, капитализация, названия
индексов) засчитываются сами по себе. Многозначные («акции», «торги», «биржа»,
«инвесторы») требуют торгового контекста в пределах 80 символов, поэтому акция
протеста, рекламная акция и торги по аренде в раздел не попадают. Кириллица
сопоставляется с юникодными границами слова: без них «внебиржевым» совпадало бы
с «биржев», «зернотрейдера» с «трейдер», а «акционерное общество» с «акционер».

Сборщик хранит исходные рубрики в поле `sourceCategories` каждой записи и
пересчитывает разделы по текущим правилам при каждом запуске, включая записи,
перенесённые из предыдущего среза. Записям, сохранённым до появления этого
поля, прежние разделы не доверяются: раздел выводится заново из адреса статьи
и правила источника по умолчанию, а если вывести нечего, остаются только
сквозные темы по тексту или запись уходит из ленты.

Правила покрыты тестами:

```bash
npm run test:classify
```

Проверить разделы по всему срезу можно скриптом аудита: он печатает каждый
раздел целиком и для каждой новости указывает, по какому правилу она туда
попала (рубрика фида, раздел в адресе, правило источника или текст):

```bash
node scripts/audit-sections.mjs              # все разделы
node scripts/audit-sections.mjs ai security  # только выбранные
```

Срез не ограничен «12/25» — это только порционная отрисовка. Реальный объём определяется сборщиком данных.

## Биржевой блок раздела «Фондовый рынок»
Когда «Фондовый рынок» выбран единственной темой, вместо крупной первой
карточки показывается блок Московской биржи: значения индексов, бегущая строка
котировок и тепловая карта. Карта — это плиточная диаграмма (squarified
treemap): площадь плитки это капитализация бумаги (или оборот, если биржа не
отдала капитализацию), цвет это дневное изменение по расходящейся шкале
«падение — нейтраль — рост», плитки сгруппированы по секторам.

Над картой стоит график индекса МосБиржи (день, неделя, месяц, с начала
года; дневной график меряется от закрытия прошлой сессии) и строка
макроиндикаторов: индекс гособлигаций RGBI, юань, доллар и евро по фиксингам
биржи, ближайший торгуемый фьючерс на Brent. Каждый из этих источников
необязателен: чего биржа не отдала, того в строке нет. Под картой три
списка лидеров дня среди ликвидных бумаг (оборот от 30 млн ₽): рост,
падение, оборот.

Клик по плитке или по строке лидеров открывает панель компании: цена,
изменение, оборот, сектор и новости ленты об этой компании. Компанию в тексте
находит словарь названий в `moex-snapshot.js`: он знает, что «Газпром нефть»
это не «Газпром», «Сберегательный» это не «Сбер», а «Лента» в новостях чаще
не ритейлер, и допускает падежи («Полюса», «Магнитом»).

Цвет никогда не единственный канал: на каждой плитке написан тикер и процент,
у плитки есть подпись для скринридера, а под картой открывается та же таблица.
Одиннадцать ступеней шкалы и цвет текста на них подобраны так, чтобы контраст
подписи был не ниже 4,5:1 в обеих темах. Бегущая строка останавливается при
наведении и полностью отключается при `prefers-reduced-motion`.

Котировки страница запрашивает у Московской биржи сама, из браузера читателя
(ISS API, `moex-snapshot.js` разбирает ответ), и обновляет их каждые пять
минут, пока раздел открыт. Так сделано не из экономии: биржа рвёт соединения
с серверов GitHub (`ECONNRESET` с раннера в Azure), поэтому собрать эти данные
в workflow нельзя, а браузеру в России она отвечает. Если обычный запрос из
браузера заблокирован, страница повторяет его через JSONP, который ISS тоже
поддерживает.

Тот же модуль использует `npm run build:moex`, который пытается положить
запасной срез в `data/moex.json`: он нужен читателям, чьей сети биржа не
отвечает. Под подписью карты видно, живые это котировки или срез от такого-то
времени. Если данных нет ниоткуда, блок честно говорит, что биржа недоступна,
а лента раздела работает как обычно. Разбор ответа биржи проверяется тестами
`npm run test:moex`.

## Авто-обновление на GitHub
В репозитории есть workflow `/.github/workflows/update-data.yml`, который (по расписанию и вручную) обновляет `data/news.json` и `data/articles/` и коммитит их в `main`. Шаг `build:moex` в нём оставлен на случай, если биржа начнёт отвечать раннерам GitHub; сейчас он ожидаемо пишет в лог `ECONNRESET`, и `data/moex.json` в коммит не попадает.

Перед записью среза сборщик редактирует секретоподобные фрагменты из внешних статей: приватные ключи, JWT, токены популярных сервисов (GitHub, Telegram, Google, OpenAI, Slack, HashiCorp Vault, Docker Swarm и другие), URL с логином/паролем и чувствительные query-параметры. Workflow дополнительно запускает `npm run check:data-secrets`, который проверяет индекс и все файлы статей, чтобы не коммитить новый срез с сильными secret-паттернами.

Правила редактирования и проверки живут в одном модуле `scripts/secrets.mjs`,
чтобы сборщик и проверка не расходились. Тесты `npm run test:secrets` собирают
образцы токенов на лету, так что в репозитории нет ни одной строки, похожей на
секрет. Если GitHub Secret Scanning сообщает о новом типе токена, достаточно
добавить его форму в этот модуль. Сами такие находки почти всегда являются
примерами из чужих статей и туториалов, а не секретами проекта: их достаточно
закрыть в GitHub как ложные срабатывания, а новые записи с тем же типом уже
не попадут в срез.

## Примечания
- Текст в модальном окне извлекается автоматически (Readability) и может быть неполным или отсутствовать для отдельных сайтов.
