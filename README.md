# Агрегатор новостей (GitHub Pages)

Статический сайт-агрегатор: выбираете одну или несколько категорий, получаете общую ленту свежих новостей.

Возможности:
- выбор нескольких категорий;
- отдельный раздел с новостями об искусственном интеллекте;
- карточки с картинкой и кратким описанием;
- бесконечная лента (порционная отрисовка);
- просмотр текста в модальном окне + ссылка на первоисточник.

Интерфейс оформлен как новостное издание: светлая и тёмная темы, навигация по темам со счётчиками,
крупная первая публикация и адаптивная сетка. На телефоне темы доступны в
горизонтальном меню. Режим чтения поддерживает изменение размера текста,
управление с клавиатуры и возврат фокуса к открытой карточке. Выбранные темы
размер текста и выбранная цветовая тема сохраняются на устройстве. До первого
ручного переключения тема следует системной настройке браузера.

Раздел `ai.html` показывает только материалы об ИИ. Сборщик присваивает им
категорию по русским и английским терминам, названиям ключевых моделей и
компаний. До следующего запуска сборщика та же классификация применяется в
браузере к текущему срезу новостей.

Проверить основные сценарии интерфейса (после `npm ci`):

```bash
npm run test:ui
```

Тесты проверяют фильтрацию и порционную загрузку на текущем `data/news.json`,
сохранение настроек, окно чтения, ошибки загрузки и повторные запросы.
Они выполняются в jsdom и не заменяют визуальную проверку в браузере.

## Как включить GitHub Pages
1. Запушьте репозиторий в GitHub.
2. GitHub: Settings -> Pages.
3. Source: "Deploy from a branch".
4. Branch: `main` / folder: `/ (root)`.

После этого откройте Pages URL.

## Локальный запуск
Можно открыть `index.html` напрямую, но надёжнее через локальный сервер:

```bash
node dev-server.js
```

## Откуда берётся текст новостей
Браузер **не может надёжно** скачать «полный текст» с сайтов новостей напрямую (CORS/пейволлы/защита).
Поэтому лента читает готовый срез `data/news.json`, который собирается отдельным скриптом.

Сгенерировать данные локально:

```bash
npm install
npm run build:data
node dev-server.js
```

Источники и правила категоризации настраиваются в `data/feeds.json`.

## Как новости попадают в разделы
Раздел новости определяется рубрикой, в которой её разместил сам источник:
это значение `<category>` из RSS, а для ТАСС и Интерфакса, у которых раздел
закодирован в адресе статьи, ещё и первый сегмент пути (`/politika`, `/world`).
Ключ вида `/politika` в `categoryMap` точнее рубрики из RSS и имеет приоритет.

Рубрика источника сопоставляется только с тем разделом сайта, которому она
действительно соответствует. Если подходящего раздела нет (например, «Авто»,
«Из жизни» и «Путешествия» на Lenta.ru), новость в ленту не попадает, а не
ставится в чужой раздел. Поверх этого к любой новости добавляются сквозные темы
«ИИ» и «Здоровье» по тексту заголовка и описания.

Сборщик хранит исходные рубрики в поле `sourceCategories` каждой записи и
пересчитывает разделы по текущим правилам при каждом запуске, включая записи,
перенесённые из предыдущего среза. Записи, сохранённые до появления этого поля,
остаются в прежних разделах, пока не выйдут из семидневной истории.

Правила покрыты тестами:

```bash
npm run test:classify
```

Срез не ограничен «12/25» — это только порционная отрисовка. Реальный объём определяется сборщиком данных.

## Авто-обновление на GitHub
В репозитории есть workflow `/.github/workflows/update-data.yml`, который (по расписанию и вручную) обновляет `data/news.json` и коммитит его в `main`.

Перед записью `data/news.json` сборщик редактирует секретоподобные фрагменты из внешних статей: приватные ключи, JWT, токены популярных сервисов, URL с логином/паролем и чувствительные query-параметры. Workflow дополнительно запускает `npm run check:data-secrets`, чтобы не коммитить новый срез с сильными secret-паттернами.

## Примечания
- Текст в модальном окне извлекается автоматически (Readability) и может быть неполным или отсутствовать для отдельных сайтов.
